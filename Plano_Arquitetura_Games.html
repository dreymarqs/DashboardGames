Arquitetura do Projeto: Sales & Metacritic

Documentação de Fluxo (Python → PostgreSQL → Power BI)

1. Fluxo de Integração e Tratamento (Python)

O Python atuará exclusivamente como a camada de ETL (Extração, Transformação e Carga), sem processamento visual. O objetivo é pegar os dados brutos e normalizá-los.

O que você vai precisar:

  • Bibliotecas: pandas (para manipulação tabular) e sqlalchemy + psycopg2 (para a conexão com o PostgreSQL).
  • Ambiente: Seu script Python rodando para fazer a leitura do arquivo CSV.

O Fluxo Lógico (Passo a Passo):

1. Extração: Carregar o CSV contendo os 50k registros em um DataFrame Pandas.
2. Limpeza: Identificar valores nulos (especialmente nas colunas de nota do Metacritic, já que jogos muito antigos não terão avaliações). Tratar esses nulos preenchendo com valores que não quebrem suas médias no futuro (ex: atribuir um identificador ou deixá-los vazios conscientemente).
3. Separação: Extrair valores únicos para criar as Tabelas Dimensão. Você vai gerar DataFrames isolados apenas com os nomes únicos de Plataformas, Gêneros e Publicadoras, e gerar um ID (chave primária) para cada um.
4. Cruzamento: Substituir os nomes em texto no DataFrame original (Tabela Fato) pelos IDs que você acabou de gerar nas Dimensões.
5. Carga: Abrir a conexão com o banco e realizar o insert das Tabelas Dimensão e, por fim, da Tabela Fato no banco PostgreSQL.

2. Estrutura do Banco de Dados (PostgreSQL)

O banco servirá como a fonte da verdade. Você pode gerenciar essa estrutura visualmente conectando um client (como DBeaver ou pgAdmin) ao seu servidor local do PostgreSQL.

O que você vai precisar:

  • O serviço do PostgreSQL rodando ativo no seu sistema (Linux ou Windows).
  • Um banco de dados criado (ex: game_intelligence).

Estrutura das Tabelas (Star Schema):

Tabela Tipo Colunas Essenciais
dim_plataforma Dimensão ID da Plataforma (PK), Nome da Plataforma.
dim_publicadora Dimensão ID da Publicadora (PK), Nome da Publicadora.
dim_genero Dimensão ID do Gênero (PK), Nome do Gênero.
dim_jogo Dimensão ID do Jogo (PK), Nome, ESRB Rating, Critic Score, User Score, GOTY (Verdadeiro/Falso), Monetização.
fato_vendas Fato ID da Venda (PK), ID do Jogo (FK), ID da Plataforma (FK), ID do Gênero (FK), ID da Publicadora (FK), Ano de Lançamento, Vendas NA, Vendas EU, Vendas JP, Vendas Outros, Vendas Globais.

3. Camada Semântica e Visual (Power BI)

Aqui é onde a análise acontece. O Power BI vai se conectar diretamente ao PostgreSQL para puxar os dados já limpos e estruturados.

O que você vai precisar fazer:

  • Conexão: Usar o conector de banco de dados PostgreSQL do Power BI Desktop.
  • Power Query: Apenas validação final (conferir se os tipos de dados estão corretos: texto como texto, número decimal como número decimal).
  • Modelagem: Na guia de Modelo, ligar o ID de cada Dimensão ao seu respectivo ID na Tabela Fato, formando o desenho de uma estrela. O filtro deve fluir das Dimensões para a Fato.

O que o Dashboard deve conter (Wireframe):

Página 1 Visão Macro e Mercado
  • Filtros: Ano, Gênero e Plataforma.
  • Cards principais: Faturamento Global, Total de Jogos, Nota Média da Crítica.
  • Gráfico de linha mostrando a evolução temporal das vendas globais ano a ano.
  • Gráfico de barras listando o ranking das publicadoras mais rentáveis.
Página 2 Recepção Crítica vs. Desempenho
  • Gráfico de dispersão cruzando a Nota do Metacritic (Eixo X) com o Volume de Vendas (Eixo Y).
  • Gráfico de colunas comparando a diferença entre as notas dadas pelos Críticos e pelos Jogadores, quebrado por gênero do jogo.
  • Matriz detalhada com os top jogos listando faturamento, se ganhou GOTY e o tipo de monetização.
Página 3 Comportamento Regional
  • Gráfico de anel mostrando o Market Share das vendas divididas pelo sistema ESRB (classificação etária).
  • Gráfico de barras empilhadas demonstrando qual porcentagem das vendas de um determinado Gênero (ex: RPG) vem de qual região (América do Norte, Europa ou Japão).
