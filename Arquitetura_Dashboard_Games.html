Arquitetura de Dados e BI

Dashboard de Video Game Sales & Metacritic Intelligence

1. Fluxo de Processamento (ETL com Python)

O fluxo de dados usará Python (com as bibliotecas pandas e sqlalchemy) para ler o CSV bruto, tratar as inconsistências e inserir os dados de forma normalizada em um banco de dados PostgreSQL.

Objetivos do Script:
  • Separar o tabelão (desnormalizado) em um Star Schema.
  • Tratar valores nulos (ex: jogos sem nota no Metacritic).
  • Criar IDs únicos para as tabelas dimensão.
  • Carregar os dados via engine do SQLAlchemy para o PostgreSQL.

Exemplo de Script Python (Pipeline ETL)

import pandas as pd
from sqlalchemy import create_engine

# 1. Extração (Extract)
df_raw = pd.read_csv('video_game_sales_metacritic.csv')

# 2. Transformação (Transform)
# Removendo ou tratando nulos
df_raw['Critic_Score'].fillna(-1, inplace=True) # -1 indica "Sem Avaliação"
df_raw['User_Score'].fillna(-1, inplace=True)
df_raw['Year_of_Release'].fillna(1900, inplace=True)

# Criando as Dimensões (Valores únicos)
dim_plataforma = pd.DataFrame(df_raw['Platform'].unique(), columns=['nome_plataforma']).reset_index()
dim_plataforma.rename(columns={'index': 'id_plataforma'}, inplace=True)

dim_publicadora = pd.DataFrame(df_raw['Publisher'].dropna().unique(), columns=['nome_publicadora']).reset_index()
dim_publicadora.rename(columns={'index': 'id_publicadora'}, inplace=True)

dim_genero = pd.DataFrame(df_raw['Genre'].dropna().unique(), columns=['nome_genero']).reset_index()
dim_genero.rename(columns={'index': 'id_genero'}, inplace=True)

# Mapeando os IDs de volta para criar a Tabela Fato
df_raw = df_raw.merge(dim_plataforma, left_on='Platform', right_on='nome_plataforma', how='left')
df_raw = df_raw.merge(dim_publicadora, left_on='Publisher', right_on='nome_publicadora', how='left')
df_raw = df_raw.merge(dim_genero, left_on='Genre', right_on='nome_genero', how='left')

# Criando a Dimensão Jogo
dim_jogo = df_raw[['Name', 'ESRB_Rating', 'Critic_Score', 'User_Score', 'Monetization', 'GOTY']].drop_duplicates().reset_index(drop=True)
dim_jogo.reset_index(inplace=True)
dim_jogo.rename(columns={'index': 'id_jogo'}, inplace=True)

# Tabela Fato
df_raw = df_raw.merge(dim_jogo, on=['Name', 'ESRB_Rating'], how='left')
fato_vendas = df_raw[['id_jogo', 'id_plataforma', 'id_publicadora', 'id_genero', 'Year_of_Release', 
                      'NA_Sales', 'EU_Sales', 'JP_Sales', 'Other_Sales', 'Global_Sales']]

# 3. Carga (Load) - Conectando ao PostgreSQL
engine = create_engine('postgresql://usuario:senha@localhost:5432/game_intelligence')

# Inserindo tabelas no banco
dim_plataforma.to_sql('dim_plataforma', engine, if_exists='replace', index=False)
dim_publicadora.to_sql('dim_publicadora', engine, if_exists='replace', index=False)
dim_genero.to_sql('dim_genero', engine, if_exists='replace', index=False)
dim_jogo.to_sql('dim_jogo', engine, if_exists='replace', index=False)
fato_vendas.to_sql('fato_vendas', engine, if_exists='replace', index=False)

print("ETL concluído com sucesso!")

2. Modelagem do Banco de Dados (PostgreSQL)

Os dados serão armazenados em uma estrutura de Star Schema otimizada para consultas analíticas pesadas. Caso precise criar as tabelas manualmente antes do insert, aqui está o DDL.

-- Criação das Tabelas Dimensão
CREATE TABLE dim_plataforma (
    id_plataforma INT PRIMARY KEY,
    nome_plataforma VARCHAR(50)
);

CREATE TABLE dim_publicadora (
    id_publicadora INT PRIMARY KEY,
    nome_publicadora VARCHAR(150)
);

CREATE TABLE dim_genero (
    id_genero INT PRIMARY KEY,
    nome_genero VARCHAR(50)
);

CREATE TABLE dim_jogo (
    id_jogo INT PRIMARY KEY,
    name VARCHAR(255),
    esrb_rating VARCHAR(10),
    critic_score DECIMAL(5,2),
    user_score DECIMAL(5,2),
    monetization VARCHAR(50),
    goty BOOLEAN
);

-- Criação da Tabela Fato
CREATE TABLE fato_vendas (
    id_venda SERIAL PRIMARY KEY,
    id_jogo INT REFERENCES dim_jogo(id_jogo),
    id_plataforma INT REFERENCES dim_plataforma(id_plataforma),
    id_publicadora INT REFERENCES dim_publicadora(id_publicadora),
    id_genero INT REFERENCES dim_genero(id_genero),
    year_of_release INT,
    na_sales DECIMAL(10,2),
    eu_sales DECIMAL(10,2),
    jp_sales DECIMAL(10,2),
    other_sales DECIMAL(10,2),
    global_sales DECIMAL(10,2)
);

3. Importação e Estrutura no Power BI

Após a ingestão no PostgreSQL, a conexão com o Power BI será direta. O ambiente deve ser configurado seguindo as melhores práticas de modelagem analítica.

Etapa Ação no Power BI / Power Query
Conexão Obter Dados > Banco de Dados PostgreSQL. Escolher o modo "Importar" (ou DirectQuery, dependendo da necessidade de atualização em tempo real).
Relacionamentos Na guia de Modelo, garanta que fato_vendas está no centro (esquema estrela). Crie relacionamentos 1:N entre as chaves primárias das dimensões e as chaves estrangeiras da Fato. O sentido do filtro deve ser ÚNICO (da Dimensão para a Fato).
Medidas DAX Essenciais Criar uma tabela vazia chamada _Medidas para organizar:
  • Total Receita Global = SUM(fato_vendas[global_sales])
  • Share Japão = SUM(fato_vendas[jp_sales]) / [Total Receita Global]
  • Score Médio Crítica = CALCULATE(AVERAGE(dim_jogo[critic_score]), dim_jogo[critic_score] > 0)

4. Estrutura do Dashboard (Telas / Views)

Para manter a legibilidade com 50k registros, o dashboard será dividido em 3 páginas principais, cada uma focada em responder um conjunto de perguntas de negócio específicas.

Página 1: Visão Executiva Macro (O C-Level)

Foco em volume financeiro, market share e desempenho ao longo do tempo.

  • Filtros Globais (Slicers): Ano de Lançamento (Slider), Geração da Plataforma, Gênero.
  • KPI Cards (Topo): Total de Vendas Globais, Volume Total de Jogos, Média de Avaliação.
  • Gráfico de Área / Linhas: Vendas Globais ao longo do tempo (Eixo X: Ano). Permite ver o crescimento e a sazonalidade da indústria.
  • Gráfico de Barras Horizontal: Top 10 Publicadoras por Venda Global (ex: Nintendo, EA, Activision).
  • Gráfico de Cascata (Waterfall): Quebra de receita por região (NA, EU, JP, Other).

Página 2: Qualidade vs. Receita (A Visão Crítica)

Cruza as pontuações do Metacritic com a performance de vendas.

  • Gráfico de Dispersão (Scatter Plot):
    • Eixo X: Nota Metacritic (Critic Score)
    • Eixo Y: Vendas Globais
    • Tamanho da Bolha: Vendas (para ênfase)
    • Cor: Gênero ou Publicadora
    *Insight esperado: Jogos acima de 85 tendem a ter um "long tail" de vendas muito maior.
  • Gráfico de Colunas Agrupadas: Comparação das médias de Critic Score vs User Score por Gênero. Onde há mais discrepância?
  • Tabela de Matriz: Top 20 Jogos Individuais, mostrando Vendas, GOTY (flag) e Scores (com formatação condicional: verde para >85, vermelho para <60).

Página 3: Análise Demográfica e Regional

Foco na distribuição ESRB e como o consumo varia geograficamente.

  • Gráfico de Barras 100% Empilhadas:
    • Eixo Y: Gêneros (RPG, Shooter, Sports, etc.)
    • Valores: % de Vendas na América do Norte, Europa e Japão.
    *Insight esperado: RPGs dominam fortemente o mercado japonês, enquanto Shooters dominam o norte-americano.
  • Gráfico de Anel (Donut Chart): Distribuição de Receita por Classificação Etária (ESRB - M, T, E, etc.).
  • Gráfico de Faixas (Ribbon Chart): Evolução do Market Share das Plataformas ao longo das décadas.
